# 攻击知识库 vs 采集队列

## 一句话区别

| | 攻击知识库 | 采集队列 |
|---|------------|------------------------|
| **是什么** | 提炼后的**攻击认知**（知识） | 采集到的**原始报告**（证据）+ 流水线任务 |
| **类比** | 维基条目 / 案例结论 | 参考文献 / ETL 作业队列 |
| **谁维护** | 流水线自动写入；分析师**可选**合并纠错 | 采集器 + 解析 + AI；**无人工审情报** |
| **检索重心** | 手法、工具、CVE、C2、勒索家族、行业 | 采集源、处理状态、自动关联知识、失败原因 |

## 攻击知识库应包含的维度（AMI 目标）

以下字段挂在 **AttackKnowledge** 上，并可与情报、实体关联查看：

| 维度 | 说明 | Demo 字段 |
|------|------|-----------|
| 攻击手法 | MITRE ATT&CK Tactic/Technique + Procedure | `techniques[]` |
| 攻击工具 | 武器化工具、商用/开源利用链 | `tools[]` |
| 攻击者基础设施 | C2、托管、扫描源、投递域名/IP | `infrastructure[]` |
| 利用漏洞 | CVE 及是否在野 | `vulnerabilities[]` |
| 恶意软件 | 家族名 + **分类**（含勒索软件等） | `malware[]` { name, class } |
| 威胁主体 / 行业 | APT、目标行业 | `threatActors`, `targetIndustries` |
| 支撑情报 | 依据哪些报告 | `linkedIntel[]` |

**采集队列**（`IntelReport`）保留：原文、采集/披露时间、来源、IOC 抽取、**流水线状态**、AI 抽取预览、`knowledgeIds`（自动关联）、`knowledgeAction`（新建/更新）。

## 典型工作流（自动化）

1. **采集配置** 拉取或推送 → 情报入队（`queued`）  
2. **解析** → **AI 抽取** TTP/实体/IOC 候选  
3. 流水线按规则写知识：**标题与已有报告相同 → 更新该知识**；**标题不同 → 新建知识** → 情报 `succeeded`  
4. 分析师在 **攻击知识库** 可选：合并重复、修正 TTP、发布知识  
5. SOC/AI 以 **攻击知识** 为主检索；溯源时打开支撑情报原文  

## 与 OpenCTI 的差异

OpenCTI 常以 **Observable（如域名）** 为检索圆心；AMI 以 **攻击知识** 为圆心，IOC 多在情报或知识的「基础设施」维度中维护，不作为首页主路径。
